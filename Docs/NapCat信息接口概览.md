# NapCat 信息接口概览

供 xiaolang 选择输入信息使用

调研日期  2026年10月10日    接口范围  NapCat OneBot 11

我们已确定使用 NapCat 提供的 OneBot 11 接口，并把 NapCat 视为黑盒。本文件列出它可以向上层应用提供的信息，供后续选择哪些需要接收、理解或保存。列出某项能力不代表 xiaolang 已决定使用它。

清单分为主动上报和主动查询两部分，覆盖信息类别及主要内容；不展开调用参数、实现步骤，也不列发送消息、禁言、修改资料等操作接口。

## 1 信息从哪里进入

| 获取方式 | 包含的信息 |
| --- | --- |
| 聊天消息 | 群聊、好友私聊、群临时会话；可选的登录账号自身消息。 |
| 事件通知 | 撤回、群成员变化、禁言、戳一戳、表情回应等。 |
| 请求和运行状态 | 好友申请、群申请或邀请、连接、心跳、账号掉线。 |
| 主动查询返回 | 历史消息、用户和群资料、文件、公告、相册及其他扩展结果。 |

## 2 一条消息的基本信息

| 信息项 | 大致包含什么 |
| --- | --- |
| 时间和账号 | 消息时间 time；接收该消息的登录 QQ 号 self_id。 |
| 聊天来源 | 群聊或私聊 message_type；好友、群临时会话、普通群消息等子类型。 |
| 发送者 | 发送者 QQ 号 user_id、昵称 nickname；群消息可带群名片 card 和成员角色 role。 |
| 群和会话 | 群号 group_id；NapCat 可补充群名称 group_name、私聊目标 target_id、临时会话来源 temp_source。 |
| 消息标识 | message_id；NapCat 另带 real_seq、real_id、message_seq 等关联标识，不应自行假定其递增或等价关系。 |
| 消息正文 | 按顺序排列的消息段 message；或配置为字符串格式。raw_message 是对应的文字及 CQ 码表示。 |
| 其他附加信息 | message_format、font；自身消息可带 message_sent_type。debug 模式可增加原始消息对象 raw。 |

昵称、名片、角色等可能缺失。年龄、性别、地区和完整人物资料不是普通消息稳定携带的信息，应与主动查询结果分开理解。

## 3 消息正文可以包含什么

一条消息可以混合文字、引用、@、图片等多个消息段，顺序可以保留。以下列出当前接收转换逻辑中的主要信息类型。

| 内容类型 | 能够取得的信息 |
| --- | --- |
| 纯文本 | 文字内容，包括普通 Unicode 表情字符。 |
| @ 提及 | 被提及者 QQ 号；all 表示全体成员。 |
| 引用或回复 | 被回复消息的关联 ID；通常不会随该消息段直接附上原消息全文。 |
| QQ 内置表情 | 表情 ID；部分类型带原始数据、结果 ID 或连击数。 |
| 图片和动图 | 文件标识或名称、URL、大小、可能存在的摘要及图片子类型。 |
| 商城表情包 | 通常转为 image；可带表情名称、图片 URL、表情 ID、包 ID 和 key。 |
| 语音 | 文件标识、大小；可能带 URL 和 NapCat 所在机器的本地路径。 |
| 视频 | 文件标识、大小；资源 URL 或可取得的本地路径。 |
| 普通文件 | 文件名称、文件 ID、大小；取得成功时可附下载地址。 |
| 在线文件和文件夹 | 消息 ID、元素 ID、文件名、大小、是否为文件夹；正文内容需另外取得。 |
| QQ 闪传 | 文件集 ID；文件集详情、列表和下载地址属于主动查询信息。 |
| 合并转发 | 转发 ID；启用解析并成功拉取时，可带内部消息及其发送者、时间、内容。 |
| JSON 卡片 | 原始卡片数据；链接、音乐、小程序、好友或群推荐、位置等通常由此表达。 |
| Markdown | 消息中的 Markdown 内容；与 xiaolang 是否采用 Markdown 回复无关。 |
| 骰子和猜拳 | 骰子点数或猜拳结果。 |
| 旧式戳一戳消息段 | 特定表情元素可转成 poke 类型及 ID；常见聊天戳一戳另以上报通知表示。 |

资源信息和资源内容是两回事。图片、语音、视频、文件上报通常给出标识、地址或路径，不保证直接携带文件字节；同一类型也不保证所有字段都存在。图片摘要不等于图像理解结果，语音消息本身不等于转写文字。

类型声明中出现的 XML、独立 music、contact、location、miniapp、node 等名称，不能据此认定都会作为独立接收消息段上报；应看具体消息转换结果。

依据  [S2] [S3]    合并转发附带正文受 parseMultMsg 配置及拉取结果影响。

## 4 聊天和群组事件通知

这些通知描述发生了什么，通常附带时间、登录账号及相关对象的标识。表中列的是可提供的信息，不表示每次都会有全部字段。

| 通知类型 | 能够取得的信息 |
| --- | --- |
| 好友添加成功 | 新增好友的 QQ 号。 |
| 私聊消息撤回 | 消息发送者 QQ 号、被撤回消息 ID。 |
| 群消息撤回 | 群号、原发送者、操作者、被撤回消息 ID；不自带原正文。 |
| 群成员增加 | 群号、新成员、操作者；批准入群或邀请入群等子类型。 |
| 群成员减少 | 群号、离群成员、操作者；主动退群、被踢、登录账号被踢及群解散等子类型。 |
| 群管理员变动 | 群号、成员、设置或取消管理员。 |
| 群禁言变化 | 群号、被操作成员、操作者、时长、禁言或解除；全员禁言按对应特殊标识表达。 |
| 群文件上传 | 群号、上传者；文件 ID、名称、大小、业务标识。 |
| 戳一戳 | 操作者和目标；群内带群号，私聊可带发送者及原始提示信息。 |
| 群名片变化 | 群号、成员、旧名片、新名片。 |
| 群名称变化 | 群号、相关用户、新群名称。 |
| 群头衔变化 | 群号、成员、头衔文字。 |
| 精华消息通知 | 群号、消息 ID、发送者、操作者及事件子类型；具体增删覆盖需按版本实测。 |
| 消息表情回应 | 群号、消息 ID、表情 ID、数量、增加或减少标志；操作人可能缺失。 |
| 输入状态 | 用户 QQ 号、状态类型和提示文字；不是对方正在输入的文字正文。 |
| 资料卡点赞 | 点赞者 QQ 号、昵称、次数、时间等。 |
| 群灰条提示 | 部分未专门归类的群提示可带群号、用户、消息 ID、业务 ID、提示内容和原始信息。 |
| 在线文件状态 | 对端 QQ 号，以及接收、拒绝、取消等传输状态。 |

消息表情回应与资料卡点赞是不同信息。官方旧兼容表对表情回应标有范围限制；当前实现也受底层事件来源和消息定位结果影响，不能当作全群完整的表情回应记录。

依据  [S1] [S6]    基础通知与 NapCat 或兼容扩展均已列入，未将其一概当作 OneBot 标准。

## 5 请求事件和运行状态

### 好友和群请求

| 请求类型 | 能够取得的信息 |
| --- | --- |
| 加好友申请 | 申请人 QQ 号、验证文字 comment、请求标识 flag。 |
| 申请加入群聊 | 群号、申请人、验证文字、请求标识、add 等子类型；接收范围取决于账号身份和 QQ 可见范围。 |
| 邀请登录账号入群 | 群号、相关用户、附言、请求标识、invite 子类型。 |

### 连接和账号状态

| 信息类型 | 能够取得的信息和条件 |
| --- | --- |
| 连接成功 | WebSocket 生命周期 connect 事件。 |
| 心跳 | online、good 等状态，以及心跳间隔 interval；能否收到取决于连接方式和配置。 |
| 账号掉线 | bot_offline 通知：登录账号、提示标题 tag 和说明 message；不能代替所有断线检测。 |
| 自身消息 | 开启 reportSelfMessage 后可上报登录账号自己发出的私聊、群聊等消息；默认关闭。 |
| 调试原始信息 | 部分连接开启 debug 后，可在消息中增加原始对象 raw；这不是稳定的业务字段契约。 |

### 文档列出但不能直接依赖的项目

| 项目 | 当前边界 |
| --- | --- |
| 启用和停用生命周期 | 枚举有 enable、disable，但官方兼容表标为不支持上报。 |
| 其他客户端状态变化 | client_status 通知在官方兼容表中标为不支持；在线客户端查询另行提供。 |
| 离线文件通知 | offline_file 在兼容表中标为不支持；文件消息、群文件上传和在线文件事件需分别看待。 |
| 匿名或系统群消息子类型 | 不能因为标准或类型定义列出就视为可收到；普通群消息以 normal 为主。 |
| 窗口抖动等旧消息类型 | 旧文档列有 shake；本快照接收转换表未见对应独立处理，列为待实测能力。 |

依据  [S1] [S4] [S5] [S6]    请求处理和发送等操作不属于本清单。

## 6 主动查询能取得的人和群信息

以下内容不会因为连接 NapCat 就全部自动传入。上层应用发起相应查询后，NapCat 才返回可取得的数据；权限、缓存、账号可见性和 QQ 返回结果都会影响内容。

| 信息类别 | 主要内容 |
| --- | --- |
| 登录账号 | 当前账号 QQ 号、昵称。 |
| 好友和好友分组 | 好友 QQ 号、昵称、备注、分组 ID 和名称；部分结果带性别、年龄、等级、QID 等附加资料。 |
| 单向好友 | 可取得的单向好友列表及标识、昵称、来源等。 |
| 用户详细资料 | QQ 号、UID、昵称、备注、性别、年龄、个性签名、QQ 等级、QID、注册时间、会员信息等，字段按实际结果为准。 |
| 用户在线状态 | 在线状态及扩展状态；不是持续可靠的在线追踪。 |
| 最近会话 | 会话对象、群或用户名称、备注、聊天类型、最近消息时间和最后一条消息。 |
| 群列表和基本资料 | 已加入的群、群号、群名称、成员数、人数上限。 |
| 群详细及扩展资料 | 群备注、全员禁言状态，以及 QQ 返回的扩展群资料。 |
| 群成员列表和详情 | 成员标识、昵称、名片、角色、头衔；可附年龄、性别、入群和最后发言时间、等级、禁言截止时间等。 |
| 禁言成员列表 | 群内禁言成员及相关状态信息。 |
| 群公告 | 公告 ID、作者、时间、文字、图片；可附阅读数、设置、发给新成员或置顶等状态。 |
| 群精华消息 | 消息标识、作者、操作者、设精时间、内容。 |
| 群荣誉和打卡 | 龙王、群聊之火等荣誉名单；今日打卡者、时间和排名。 |
| 群请求和系统通知 | 入群申请、邀请、忽略或过滤的请求及处理状态；另有可疑好友申请查询。 |
| 群分享和使用额度 | 群分享链接；能否 @ 全体及剩余次数等能力或额度信息。 |

某些资料结构允许生日、联系电话、邮箱等附加项，但不代表任意用户资料都可取得。资料查询返回的是账号可见的数据，也不能直接当作已核实的现实身份或人物记忆。

依据  [S7] [S8]    本节按信息类别合并相关查询，不逐项列参数和调用路径。

## 7 主动查询能取得的消息和资源信息

| 信息类别 | 主要内容和条件 |
| --- | --- |
| 指定消息 | 发送时间、作者、群或私聊来源、正文及标识；部分结果带已有表情回应列表。 |
| 群聊和私聊历史 | 可取得的历史消息列表及每条消息的基本信息；不保证无限历史、完整补齐或撤回正文可恢复。 |
| 合并转发正文 | 转发内部消息、发送者、时间、嵌套内容；受资源有效性和拉取结果影响。 |
| 表情回应明细 | 某条消息的回应表情、数量和参与用户；可附昵称、头像地址、分页状态。 |
| 图片语音及普通文件 | 文件信息、下载 URL、本地路径；部分接口可返回 Base64 或下载数据。语音可请求格式转换结果。 |
| 群文件库 | 空间和数量统计、文件夹、文件列表、文件属性与下载地址。 |
| 在线文件和闪传 | 在线文件消息列表；闪传文件集 ID、详情、文件列表、分享链接和下载地址。 |
| 个人表情和收藏 | 登录账号可取得的自定义表情 URL 或详情，以及收藏列表。 |
| 群相册 | 相册列表、相册中的图片或视频等媒体列表及其元数据。 |
| 图片文字识别 | 主动调用 QQ 提供的 OCR 能力后返回识别结果；不是图片消息自动附带的信息。 |
| 语音转文字 | 主动按消息查询 QQ 的转写结果；可能失败，不保证每条语音都可转换。 |
| 词语翻译 | 英文单词翻译结果，属于按需调用的扩展。 |
| QQ AI 语音资源 | 可用角色 ID、名称、试听地址；另有按文字生成语音后返回的资源地址，不是收到的聊天内容。 |
| 资料卡点赞记录 | 点赞详情、用户列表、次数、时间等。 |

### 辅助信息和实现占位

另有运行状态、NapCat 和协议版本、在线客户端、图片或语音发送能力、Packet 状态、机器人 QQ 号范围、设备机型显示、URL 安全等级等查询。部分结果只是能力标志或原始扩展数据。

接口还暴露 Cookies、CSRF Token、ClientKey、RKey 等登录或资源访问凭据，以及用于分享的小程序 Ark 数据。它们属于技术辅助信息，不是普通聊天内容；本清单只记录其存在，不读取或记录实际凭据。

频道列表和频道个人资料接口在核对快照中是空实现，不能列为可用的信息来源。流式下载测试等开发测试接口也不属于真实 QQ 信息。

## 8 判断是否使用时需要保留的边界

### 消息输入的可见范围

NapCat 只能提供登录账号能够接收或查询到的信息。它不是任意 QQ 用户、任意群或全部 QQ 历史的读取入口。主动上报的普通群消息不要求必须 @ 机器人。

### 主动上报不等于历史同步

当前接收逻辑会跳过早于启动时间的普通消息。断线或启动前消息不能预设会自动补齐；历史查询是另一条信息获取途径，其范围同样有限。撤回通知通常只有关联标识和操作者等信息。

### 资源地址不等于永久可用内容

媒体和文件通常先传标识、URL 或本地路径。路径属于 NapCat 所在机器，不一定能从 xiaolang 所在环境直接访问；地址、标识和文件是否仍可取得，要以实际获取结果为准。

### 原始信息不等于语义判断

NapCat 不会自动告诉我们谁在开玩笑、表情包适合什么情境、这句话是否应记住或机器人是否该接话。这些判断属于后续功能。OCR 和语音转写虽有独立查询能力，也不等于完整理解。

### 版本和条件需要保留

本文按 2026年10月10日核对的 main 快照 ff37736a4a3e2be0268f17091300b67f49931d5c 整理。选定部署版本后，应以该版本接口和实际收包为准。标准字段、NapCat 扩展、可选字段及受配置控制的内容应分开记录。
