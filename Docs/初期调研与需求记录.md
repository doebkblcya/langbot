## 2. 消息来源：已确认

- 使用 NapCat 提供的 OneBot 11 接口作为 QQ 消息来源。
- 将 NapCat 及其 OneBot 接口视为黑盒，不修改内部实现。
- 关注收到的消息与事件，以及必要的查询、发送能力。
- 详细信息类别见 [NapCat 信息接口概览](NapCat信息接口概览.md)。列出接口能力不代表决定使用全部信息。

NapCat 能提供的内容主要分为：聊天消息、事件通知、好友与群请求、运行状态，以及主动查询得到的用户／群资料、历史消息和媒体文件等信息。

边界：自动上报与主动查询不同；资源标识、地址与资源内容不同；字段可能缺失或受配置、权限、版本影响；断线和启动前的消息不能假定自动补齐。

### 5.1 AstrBot 阶段的主链路与插件化讨论（历史记录，2026-10-13）

当时用户确认采用 AstrBot 成熟链路，允许按需精简；主链路也视为可组合、可替换的能力，其余模块像积木一样逐步接入。随后用户提出 TypeScript／Koishi 新路线，本节方案已暂停；当前状态见第 5.3 节。

2026-10-13 补充澄清：用户要基于 AstrBot 成熟源码形成完整小狼项目，主链路作为小狼自身的内置插件。助手此前将交付物缩成“单独部署原版 AstrBot 后叠加小狼插件”的理解不符合目标，该交付路线已撤回。

当时助手建议：从锁定版本的 AstrBot 源码派生，保留来源、历史与许可证；小狼拥有自己的启动入口、构建镜像、配置和内置聊天插件，基础会话、人设、模型、工具循环与发送能力尽量复用成熟实现。先跑通文本闭环，再根据实际依赖收敛插件接口并精简功能。此源码路线现已暂停。

进一步方案见 [主链路插件化方案](主链路插件化方案.md)：助手建议克隆后增量重构，真正调整启动装配与聊天流程边界；用户所说的 Honeyse／Honeys 为 DeepSeek Harness 的语音转写，不另列参考项目。该具体源码路线仍为助手建议。

待验证：AstrBot 原有消息管线并非整体可卸载插件。需要核实自有入口如何复用完整聊天执行流程，并保证默认回复与自有入口不会同时生成回复；插件化边界不能只靠改名或目录拆分认定已完成。

实施进度：已将 AstrBot v4.28.2（提交 `3c7adafa1397e182d60b1016bf88759265113c8a`）克隆到本地临时参考目录并阅读接入源码，未安装依赖、启动机器人或编写业务代码。NAS 仅做过只读检查。

### 5.3 TypeScript＋Cordis 4 自写主链路（当前方向，2026-10-14）

用户明确选择从头编写小狼，使用 Cordis 4 和 TypeScript，现有项目作为代码与机制参考；不再使用 Python。主链路自身为插件，其他能力按需接入。成熟网络、数据库和模型客户端库仍可评估复用，具体依赖未决定。

用户要求先调查路线问题，并按执行链路列出完整功能与细节，暂不写代码。已形成 [主链路功能与执行流程](主链路功能与执行流程.md)：启动接入、消息观察与触发、调度与上下文、模型／工具循环、发送与结算，以及异常、插件和后续模块接入。具体默认策略仍标为助手建议，按大模块继续讨论。

## 6. AstrBot 与 MaiBot 的初期拆解

以下是功能目录，不能据此认定对应源码可以独立搬运。同一行不一定表示等价功能。核心功能、可选能力和第三方插件的具体边界需按选定版本核对。

| AstrBot | MaiBot（麦麦） |
| --- | --- |
| 消息接入、过滤与触发 | 消息接入、发言时机与参与频率 |
| 会话与上下文管理 | 聊天上下文与历史回想 |
| 人设与回复生成 | 人设与回复生成 |
| Agent 规划与工具调用 | 行动规划与工具调用 |
| 文档知识库 | 长期记忆与人物画像 |
| 图片、语音等多媒体处理 | 图片、语音等多媒体处理 |
| 模型接入与管理 | 模型接入与管理 |
| 定时任务与主动消息 | 表达方式与黑话学习 |
| 插件扩展 | 表情包收集与选用 |
| 管理界面、配置与日志 | 行为学习与注意力机制（实验性） |
| — | 插件扩展；管理界面、配置与日志 |

初期核实到的情况：

- 两者核心后端均使用 Python；本次检查的 Agent 主流程均由项目自行组织，不能因为使用 FastAPI 等 Web 框架就认为 Agent 由该框架搭建。
- AstrBot 的内置 `ToolLoopAgentRunner` 负责模型与工具调用循环，也有外部 Agent 服务接入方式。
- MaiBot 的 `MaisakaReasoningEngine` 等核心流程负责行动规划与工具循环；表达学习、黑话学习、表情包管理有各自实现。
- MaiBot 当前有 A_Memorix 记忆子系统，其文档默认配置关闭。短期上下文、历史回想与长期记忆需要分开理解。
- MaiBot 的表达学习路径主要是提取、保存、选择表达材料供回复使用，不等于持续训练模型权重。
- MaiBot 当前 QQ 连接器与旧独立 NapCat 适配器的组织方式已有变化，研究时需避免混用旧教程。

助手判断：MaiBot 更值得研究拟人聊天、表达学习、表情包与记忆；AstrBot 更值得研究消息处理、模型接入、工具和扩展方式。这是研究方向建议，不是复用选型，也不是效果评测结论。

2026-10-11 补充：已将外部项目 LangBot 加入底座候选，详见 [LangBot 初期调研](LangBot初期调研.md)。它包含消息流水线、Agent、插件与管理能力，并有官方长期记忆插件可进一步评估。当前未决定采用，原有九个功能模块及已确认需求保持不变。

三者的历史对照与启动顺序见 [底座评估与启动建议](底座评估与启动建议.md)。当时助手建议先在 NAS 验证 AstrBot，LangBot 保留为替代候选，MaiBot 重点借鉴聊天机制；未部署。2026-10-14 已确定 Cordis 4 自写路线，当前方向见第 5.3 节。
