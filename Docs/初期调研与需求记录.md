# xiaolang 初期调研与需求记录

本文记录当前讨论结果，区分已确认需求、调研结论、助手建议和待讨论事项。当前阶段只整理需求与调研，不编写业务代码、搭建骨架或引入依赖。后续项目文档使用 Markdown。

## 2. 消息来源：已确认

- 使用 NapCat 提供的 OneBot 11 接口作为 QQ 消息来源。
- 将 NapCat 及其 OneBot 接口视为黑盒，不修改内部实现。
- 关注收到的消息与事件，以及必要的查询、发送能力。
- 详细信息类别见 [NapCat 信息接口概览](NapCat信息接口概览.md)。列出接口能力不代表决定使用全部信息。

NapCat 能提供的内容主要分为：聊天消息、事件通知、好友与群请求、运行状态，以及主动查询得到的用户／群资料、历史消息和媒体文件等信息。

边界：自动上报与主动查询不同；资源标识、地址与资源内容不同；字段可能缺失或受配置、权限、版本影响；断线和启动前的消息不能假定自动补齐。

这些是功能职责划分，不代表已确定对应的框架、服务数量或目录结构。

## 4. 九个功能模块：用户已确认

| 模块 | 已确认范围 | 待讨论或调研 |
| --- | --- | --- |
| 触发与调度 | 群聊、私聊均运行。私聊普通消息默认回复。群聊默认由 @ 机器人、关键词或自定义触发词触发。主动插话使用独立 Toggle，开启后才使用。定时任务和主动消息归入此模块。 | 主动插话策略；开关作用范围；触发词匹配方式；定时任务与主动消息的具体场景。 |
| 人设与回复生成 | 使用一个统一人设，不同群共用，不做多种人设。 | 人设内容、提示词组织和回复风格，需要继续讨论与调研。 |
| 规划与工具调用 | AI 自主规划如何回应，选择并自动执行已接入的工具、脚本、Skill 等；用户要求无需逐次确认。 | 首批工具与接入方式。“NCP”暂按 MCP 理解，具体协议待核实。电脑操作不在当前范围。 |
| Memory | 提供跨会话、持久化的信息记忆；知识资料、长期记忆、人物信息和历史回想在功能上统一归入 Memory。通过对话让 AI 纠正、删除记忆。 | 记录与检索策略；不同群之间是否共享及共享范围；查看方式；具体实现方案。ChatGPT Memory 作为用户描述的体验参考。 |
| 图片处理 | 直接使用支持图片输入的模型理解图片，理解结果进入上下文。语音后续再说。 | 用户计划接入 DeepSeek v4.1 Flash；具体模型标识、接口和图片能力尚未核实。资源取得、上下文组织与缓存方式待设计。 |
| 自学习 | 可按设定时间学习聊天内容，根据需要记录和更新，例如学习语言风格。 | 学习来源、内容、方法、周期和效果评估；效果合适后可考虑直接生效，当前未确认自动生效。 |
| 简单插件扩展 | 初期方便自己增加模块，保持可扩展；不建设面向第三方的插件生态。 | 简单的扩展约定与模块接入方式。 |
| 表情包收集与选用 | 自动收集并在适当场景选用，参考用户提到的 AstrBot 表情包插件。 | 具体插件名称／仓库及版本待核实；复用方式与许可证；跨群共用方式；发送频率。 |
| 基础管理界面 | 提供基础管理能力，跟随已有功能增加对应管理入口。具体页面方案由助手提出。 | 随功能范围确定页面，暂无完整页面清单。 |

自学习任务由“触发与调度”启动；学习结果供 Memory 或相关功能模块使用。归入同一功能模块，不意味着必须使用同一数据库或算法。

## 6. AstrBot 与 MaiBot 的初期拆解

以下是功能目录，不能据此认定对应源码可以独立搬运。同一行不一定表示等价功能。核心功能、可选能力和第三方插件的具体边界需按选定版本核对。

| AstrBot | MaiBot（麦麦） |
| --- | --- |
| 消息接入、过滤与触发 | 消息接入、发言时机与参与频率 |
| 会话与上下文管理 | 聊天上下文与历史回想 |
| 人设与回复生成 | 人设与回复生成 |
| Agent 规划与工具调用 | 行动规划与工具调用 |
| 文档知识库 | 长期记忆与人物画像 |
| 图片、语音等多媒体处理 | 图片、语音等多媒体处理 |
| 模型接入与管理 | 模型接入与管理 |
| 定时任务与主动消息 | 表达方式与黑话学习 |
| 插件扩展 | 表情包收集与选用 |
| 管理界面、配置与日志 | 行为学习与注意力机制（实验性） |
| — | 插件扩展；管理界面、配置与日志 |

初期核实到的情况：

- 两者核心后端均使用 Python；本次检查的 Agent 主流程均由项目自行组织，不能因为使用 FastAPI 等 Web 框架就认为 Agent 由该框架搭建。
- AstrBot 的内置 `ToolLoopAgentRunner` 负责模型与工具调用循环，也有外部 Agent 服务接入方式。
- MaiBot 的 `MaisakaReasoningEngine` 等核心流程负责行动规划与工具循环；表达学习、黑话学习、表情包管理有各自实现。
- MaiBot 当前有 A_Memorix 记忆子系统，其文档默认配置关闭。短期上下文、历史回想与长期记忆需要分开理解。
- MaiBot 的表达学习路径主要是提取、保存、选择表达材料供回复使用，不等于持续训练模型权重。
- MaiBot 当前 QQ 连接器与旧独立 NapCat 适配器的组织方式已有变化，研究时需避免混用旧教程。

助手判断：MaiBot 更值得研究拟人聊天、表达学习、表情包与记忆；AstrBot 更值得研究消息处理、模型接入、工具和扩展方式。这是研究方向建议，不是复用选型，也不是效果评测结论。

2026-10-11 补充：已将外部项目 LangBot 加入底座候选，详见 [LangBot 初期调研](LangBot初期调研.md)。它包含消息流水线、Agent、插件与管理能力，并有官方长期记忆插件可进一步评估。当前未决定采用，原有九个功能模块及已确认需求保持不变。

三者的进一步对照与启动顺序见 [底座评估与启动建议](底座评估与启动建议.md)。本次助手建议先在 NAS 验证 AstrBot，LangBot 保留为替代候选，MaiBot 重点借鉴聊天机制；这是候选验证顺序，尚未确认底座，也未部署。新调查发现 AstrBot 也有长期记忆、自学习和表情包插件，不能只按核心内置功能比较。

## 7. 后续调研清单

| 事项 | 需要产出的结果 |
| --- | --- |
| 主动插话 | 候选机制、行为示例和复杂度，供用户判断。 |
| 统一人设 | 简单的人设组织方案与回复示例。 |
| Memory | 写入、检索、跨会话使用、纠错删除，以及跨群共享的方案比较。 |
| 自学习 | 学习材料、更新对象、执行周期、评估与生效方式。 |
| 表情包插件 | 核实具体项目和版本，检查自动收集实现、依赖及许可证。 |
| 复用评估 | 每块分别判断直接使用、适配复用或借鉴后精简实现，列出依赖和成本。 |
| 部署与模型 | 核实 NAS CPU／资源、Docker 环境，以及候选模型接口和图片输入能力。 |

助手建议：先明确行为范围，再作技术选择；保持实现克制，按实际需要评估插件和 Agent 机制。
