**基础文字聊天已经跑通，并在 NAS 上使用；接下来逐块增加聊天理解、记忆、人设和行动能力。**

## 已经能做什么

| 能力 | 现在的情况 |
| --- | --- |
| QQ 文字聊天 | 已接入 QQ 官方机器人正式环境。私聊默认回复，群里 @ 或句中出现触发词时回复。私聊和群触发词消息已有真实收发记录。 |
| 接着当前聊天回复 | 能读取本会话最近的文字历史，附有用户标识和消息时间；后台按群／私聊隔离。提示词尚未统一说明来源群、当前现实时间；目前使用临时人设。 |
| 调用工具 | 已有模型选择工具、执行、继续生成回复的基础流程；目前只有查询时间的示例工具。 |
| 故障提示 | 处理失败时可在 QQ 提示中文原因、错误码和轮次编号；后台可查看对应记录。 |
| 管理面板 | 能看运行状态、聊天和过程日志，修改模型、QQ 和触发配置。保存后应用并重启生效。 |
| 插件管理 | 当前 15 个内置、2 个外挂插件全部列出；能看详情。内置无启停按钮，外挂可按依赖启停、编辑已声明的配置。触发规则在“消息触发”插件里修改。 |
| NAS 部署 | Docker 已运行，配置、插件和聊天记录都已迁移。用户发送“迁移测试”后，模型正常生成回复，QQ 返回发送回执。VPS 的小狼部署已清理。 |

| 人设与学习 | 临时 System Prompt。 | 完整人设插件、可配置的表达风格，以及学习聊天材料并用于记忆或人设。 |

### 持续完善

以下由助手结合当前功能和实际问题安排，不作为需要用户逐项确认的产品需求，也不表示现有基础能力全部缺失。

- 调度：维护排队、并发、取消、超时和任务状态；随主动／定时任务补持久化和恢复，避免重复执行。合并、打断等策略按实际需要处理。
- 发送与异常：维护分段、去重、回执和故障反馈，避免未知结果导致重复发送或重复工具操作。
- 数据与日志：维护现有聊天记录、故障记录和日志展示，针对实际问题修复。

- 插件维护：完善服务替换、依赖检查、状态展示和资源清理；不为了插件化无限细拆。

### 现有工程基础

已实现消息去重与会话隔离、同会话排队、并发限制、模型请求超时与有限重试、工具参数检查、分段发送记录及重启后的状态标记。发送结果未知时不自动重发。故障反馈每轮最多尝试一次，不泄露原始异常或凭证。

当前调度仍是逐条排队；连续消息合并、打断正在进行的回复、重启后自动续跑任务均未实现。“持续完善”是工作安排，不是完成清单；最近文档整理没有追加实现这些优化。
