# 底座评估与启动建议

日期：2026-10-11。依据公开文档、固定版本源码及插件实现；尚未在 NAS 部署或验证效果。

## 1. 当前建议

**先把 AstrBot 作为第一个验证候选，LangBot 保留为替代候选，MaiBot 重点借鉴聊天机制。**这是助手建议，不是已确认选型。

理由是 AstrBot 的消息监听与回复触发可以分开，已有接近需求的表情包插件，也有 Memory、自学习插件可评估。它提供了一条先配置基础聊天、再逐个加模块的路径。社区插件的存在不代表可直接组合或已经满足需求。

此前优先推荐 LangBot 的依据不足。LangBot 的工程组织和官方 Memory 插件值得肯定，但不能直接推出它最适合本项目。

| 候选 | 对我们最有用的部分 | 主要适配工作 | 本次定位 |
| --- | --- | --- | --- |
| AstrBot | 基础聊天、工具扩展；表情包及学习类插件候选。 | 筛选插件，统一 Memory 和提示词注入，补齐我们的触发与开关规则。 | 首个验证候选。 |
| LangBot | 消息流水线、Agent、管理界面；官方长期记忆插件。 | 研究自学习和表情包接入；核对正式版与新版插件的兼容。 | 替代候选，尤其值得对照 Memory。 |
| MaiBot | 表达学习、黑话、表情包及自然参与聊天的现成实现。 | 让现有聊天决策严格服从私聊／群聊触发规则，确认各机制能独立关闭和替换。 | 机制参考；若以后优先追求其整套聊天行为，可重新评估底座。 |

这不是性能排名。尚无同硬件、同模型的内存、CPU、延迟、模型调用成本和聊天质量实测。

## 2. 对照九个模块

“已有”表示找到实现；“插件候选”表示找到可研究的插件；“需补”表示我们的具体行为仍有缺口。三者都有基础接入、模型调用、会话和管理能力，差别主要在功能组合及适配成本。

| 模块 | AstrBot | LangBot | MaiBot |
| --- | --- | --- | --- |
| 触发与调度 | 已有私聊默认回复、群 @／前缀、定时能力；关键词匹配与主动插话 Toggle 需对齐。 | 已有群 @／前缀／正则等；自然插话和自学习调度需补。 | 已有发言门控和规划；严格触发、默认必回需要验证和适配。 |
| 人设与回复生成 | 已有；统一选用一个人设。 | 已有；统一配置提示词。 | 已有；需处理表达学习等对人设的影响。 |
| 规划与工具调用 | 已有 Agent 工具循环、插件工具、MCP、Skills。 | 已有 Agent、插件工具、MCP、Skills。 | 已有规划、工具、MCP；未核实独立 Skills 机制。 |
| Memory | Memorix、LivingMemory 等插件候选；纠错删除与共享规则仍需逐项核实。 | 官方 LongTermMemory 有记忆、召回、资料更新、删除工具；版本和共享范围需核实。 | 已有 A_Memorix 等；对话纠错删除是否满足要求未验证。 |
| 图片处理 | 已有模型图片输入路径，目标模型兼容待测。 | 已有图片输入路径，目标模型兼容待测。 | 已有图片处理路径，目标模型兼容待测。 |
| 自学习 | 找到群聊收集、表达学习及注入插件；功能过宽，不能整包默认启用。 | 未核实到符合要求的定时语言风格学习链路。 | 已有表达与黑话学习；不等于我们要求的固定时间学习流程。 |
| 简单插件扩展 | 已有事件、模型前后处理、工具和配置扩展点。 | 已有插件 SDK、事件、工具及运行时。 | 已有插件运行时与 Hook 等扩展点。 |
| 表情包收集与选用 | 找到“表情包小偷”候选，收集、分类、搜索、发送链路较接近需求。 | 未核实到等价的现成插件；不能直接安装 AstrBot 插件。 | 已有原生表情包管理和选用。 |
| 基础管理界面 | 已有；部分候选插件带管理页。 | 已有；长期记忆插件带 Memory Console。 | 已有；具体功能入口仍需核实。 |

以上比较的源码和插件来源见第 6 节；“未核实”不代表项目没有该能力。

## 3. 四个决定适配成本的发现

### 3.1 普通群聊也要能被采集，但不因此回复

自学习和表情包收集需要看到未 @ 机器人的普通群聊，所以不能在最前面丢弃所有未触发消息。

AstrBot v4.28.2 的源码将插件监听与默认模型回复分开：全消息插件可以处理消息，默认回复另检查 @／唤醒标记。普通监听本身不会自动触发默认模型回复；插件仍可能主动调用模型或发送消息，需分别检查。[唤醒检查](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.2/astrbot/core/pipeline/waking_check/stage.py)、[处理阶段](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.2/astrbot/core/pipeline/process_stage/stage.py)

MaiBot 有消息观察、拦截 Hook，不能断言必须改核心。但在消息入队前拦截可能同时影响上下文积累，而现有发言门控后还有规划决策。要验证的是“保留消息供记忆和学习，同时严格控制回复”，不是只加一个过滤器。[消息接收实现](https://github.com/Mai-with-u/MaiBot/blob/f9ec3670a3638d6a4708ee5253f7ffe2838c9415/src/chat/message_receive/bot.py)、[发言门控](https://github.com/Mai-with-u/MaiBot/blob/f9ec3670a3638d6a4708ee5253f7ffe2838c9415/src/maisaka/turn_trigger/gates.py)

LangBot 新版源码有插件事件接入路径；正式版上能否在触发过滤之前稳定采集普通群聊，本次未完成确认，应作为替代候选的必验项。

### 3.2 Memory 先选一个负责人

LangBot 官方插件将稳定资料与事件记忆分开，提供 `remember`、`recall_memory`、`update_profile`、`forget`。稳定资料按会话／发言人保存，事件记忆可以按会话或机器人范围检索，不能理解成所有信息都可直接跨群共享。[插件说明](https://github.com/langbot-app/langbot-plugins/blob/a18c619e58c6b71ab584c6043603586184c3287b/KnowledgeEngine/LongTermMemory/README.md)

AstrBot 的 Memorix 已有 AI 管理工具，但管理操作检查 AstrBot 管理员身份；LivingMemory 当前查到的 AI 工具主要是记住与召回，删除另有管理命令。二者都需要对照“通过对话纠正、删除”的体验验证，不能只看都有记忆功能。[Memorix 工具实现](https://github.com/exynos967/astrbot_plugin_memorix/blob/0ecb96e2db0f1edacece6638e3c26da3dc332e60/memorix/tools.py)、[LivingMemory 入口](https://github.com/gongzhudeng/astrbot_plugin_livingmemory/blob/27c5b6b6903622eaf9722b3e06d3d5d213ee03d6/main.py)

助手建议：初期只启用一个长期记忆系统。自学习输出作为风格材料交给回复模块，避免两个插件都存人物画像、同时改人设、重复注入历史。这是职责建议，不是数据库选型。

### 3.3 自学习有参考实现，但需要精简

找到的 AstrBot 自学习插件支持群消息采集、按群间隔执行、表达材料提取及回复前注入，也包含社交关系、好感度、人设演化等功能。它比我们的范围大，不能因为有现成插件就全部接入。[插件仓库与说明](https://github.com/NickCharlie/astrbot_plugin_self_learning/tree/8f9edef86d7798706e97e563e1818d7aa496d435)

MaiBot 的表达学习也值得参考，但部分学习由上下文淘汰等流程触发，和固定时间执行不是同一机制。[表达学习实现](https://github.com/Mai-with-u/MaiBot/blob/f9ec3670a3638d6a4708ee5253f7ffe2838c9415/src/learners/expression_learner.py)

助手建议：先让学习任务产出可查看的候选表达，评估是否学到了群友的语言习惯、是否学偏或重复学习机器人自己的输出，再讨论自动生效。当前没有确认直接改人设或训练模型权重。

### 3.4 表情包可以先复用；Skills 要单独看运行环境

发现的 `astrbot_plugin_stealer`（表情包小偷）有自动收集、视觉分类、可选语义检索、搜索／发送工具、收集与发送独立开关，以及群内／公共图库范围。它是优先核实的候选，但尚未确认就是用户之前提到的插件，也未实测效果。[插件说明](https://github.com/nagatoquin33/astrbot_plugin_stealer/blob/36ce05e8665a19d643adbf580f5cec5348f1b716/README.md)

不做电脑操作，不意味着脚本和 Skills 无需运行环境。AstrBot 的 Skills 读取及脚本执行依赖 Local 或 Sandbox 能力；LangBot 的相关能力也依赖 Box 等配置。可以先接普通工具或 HTTP MCP，随后按实际 Skill 需求决定执行环境。[AstrBot Skills](https://docs.astrbot.app/en/use/skills.html)、[LangBot Skills](https://langbot.app/docs/zh/usage/skills/readme/)

## 4. 应该从哪里开始

以下是建议执行顺序，不是已经开始实施，也没有调整九个模块的已确认范围。

| 顺序 | 做什么 | 验收重点 |
| --- | --- | --- |
| 1 | 把基础聊天行为写成一页验收清单；确定 Memory 共享规则和统一人设的第一稿。 | 私聊默认回复；群 @／触发词回复；主动插话关闭时不插话。明确前缀、包含词等匹配方式，不重复讨论已确认规则。 |
| 2 | 核实 NAS 架构、资源、Docker 和模型接口，锁定候选版本及插件兼容。 | 镜像和依赖能适配 NAS；目标模型确实支持图片输入与工具调用。用户提到的模型名称目前不能当作已经验证的能力。 |
| 3 | 在 NAS 上部署最小 AstrBot 验证环境：NapCat、AstrBot、一个模型、一个统一人设。 | 私聊、群触发、图片输入、重连、重启保存配置；普通群聊能被采集但不引起回复。必要时补一个小模块，先不安装全部插件。 |
| 4 | 加一个简单工具，选一个 Memory 候选。 | AI 自主调用工具；记住信息、跨会话召回、对话纠正和删除、重启持久化；不串群或串人。跨群用例按最终确认的共享规则测试。 |
| 5 | 单独接入表情包，再评估自学习。 | 收集不导致乱回复；选图适合当前聊天；学习结果可查看、可停用，生效方式另行确定。 |
| 6 | 最后研究主动插话和更多调度场景。 | Toggle 能控制主动参与；策略符合克制聊天目标，不把随机概率直接当成自然插话。 |

Memory 共享仍待用户决定。可供讨论的起点是“群内事件按群保存，同一人的稳定资料按明确规则共享”；此方案尚未确认。表情包发送频率、自学习生效方式可在对应步骤讨论，不阻塞基础验证。

底座通过验证后，优先通过插件扩展；本仓库保存我们自己的文档、模块和部署配置，尽量减少核心改动。若 AstrBot 的关键行为只能靠持续修改核心实现，或 Memory 插件成本明显超出需求，再用同一份验收清单验证 LangBot；无需先重写六块基建。

## 5. 部署与开源边界

- 三者都有 Docker 路线。AstrBot 基础 Compose 可先运行主服务；LangBot 当前方案另有插件运行时及可选 Box。服务数量不能代替实际资源测量，也不应把开发分支的组合直接套到正式版。[AstrBot Compose](https://github.com/AstrBotDevs/AstrBot/blob/170eeca08bbda374228abad9f91cb4588773e4b7/compose.yml)、[LangBot Compose](https://github.com/langbot-app/LangBot/blob/0b5b4cca59500f1cbc0f106e6dcbef2f682ed4a2/docker/docker-compose.yaml)
- AstrBot 核心标注 AGPL-3.0，MaiBot 核心 GPL-3.0，LangBot 核心 Apache-2.0。调查的上述 AstrBot 插件也有自己的许可证，不能用底座许可证概括所有模块。选定复用文件后，再确定本项目的开源方式与许可证。[AstrBot](https://github.com/AstrBotDevs/AstrBot/blob/170eeca08bbda374228abad9f91cb4588773e4b7/LICENSE)、[MaiBot](https://github.com/Mai-with-u/MaiBot/blob/f9ec3670a3638d6a4708ee5253f7ffe2838c9415/LICENSE)、[LangBot](https://github.com/langbot-app/LangBot/blob/0b5b4cca59500f1cbc0f106e6dcbef2f682ed4a2/LICENSE)
- 不先增加独立 Agent 框架、向量数据库或自建管理站。是否需要这些，应由选中的模块和实测结果决定。
